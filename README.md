# MAGTRACE

気になる言葉が雑誌でいつ、どのような文脈で語られてきたかを調べるWebアプリの設計資料。
学生、クリエイター、編集・企画担当者が、掲載傾向から原典へたどる調査の入口を想定する。
このリポジトリには要件・UX検証記録・デザイン指針があり、実行できるアプリコードはない。

## 記事一覧だけでは見えない、言葉の時間変化を調べる

SNSで見つけた言葉を検索しても、個々の記事の一覧だけでは関心の移り変わりを把握しにくい。
雑誌記事の書誌メタデータを年代別に整理し、件数の推移と記事タイトルから文脈を読み、原典で確かめる体験を目指す。
AIの説明だけで完結させず、出典と収録範囲を利用者が確認できることを重視する。

## NDLの雑誌記事メタデータに絞る理由

MVPはNDLサーチの `zassaku`・`zassaku-online` に限定する設計。
API利用料と秘密鍵の管理を避け、扱う権利範囲を本文・画像から切り離すための選択である。
Google Booksはキー・クォータ・画像条件の管理に対し、表紙を使わない段階での便益が小さく保留した。
楽天ブックスは販売中の雑誌や購入導線に適するため、調査・発見を中心とするMVPでは採用しない。
Crossrefは学術誌モードを追加する場合の候補に留める。

## API利用と数値の解釈で守る境界

以下は[要件定義](docs/requirements.md)に残る2026-08-29時点の採用前提である。

- NDLと提供機関のクレジット、CC BYのリンクを表示し、継続アクセス前に利用内容をNDLへ連絡する。
- 外部APIへの負荷を抑えるため、サーバー経由の取得、最低24時間のキャッシュ、逐次実行、バックオフを前提とする。
- 件数はNDLサーチAPIの収録範囲内に限る。社会全体の流行や「初出」を断定しない。
- 代表記事の取得順を社会的な代表性と取り違えない。選定基準を表示する。
- 共有カードにも収録範囲と出典を残す。取得データで裏づけられない因果関係を生成しない。
- 公開前に利用条件と表示を再確認し、商用化時には対象データと最新条件を再監査する。

## 数字を並べる画面から、根拠をたどれる画面へ

初期UIは同じ強さのカードが並び、数字から何を読み取るかが曖昧だった。
UX改善では一文の発見、注釈付き推移、関連語、代表記事・原典の順に情報の強弱を付けた。
連続した時間変化を追いやすくするため、密な棒グラフを折れ線へ改める方針を採った。
検索語を持たない人にもテーマから入れる入口を設け、0件・障害時も次の検索へ進める設計にする。

[UX検証記録](docs/ux-harness-v0.2.md)の合格項目はFigma上のレイアウト確認であり、実データや実装の動作確認ではない。
画面内の数値と記事名はUIサンプルとして扱う。[デザイン指針](design-system/magtrace/MASTER.md)もこの前提で参照する。

## MVPに含めないもの

雑誌本文の取得・転載・生成AIによる本文要約、無許諾の表紙表示は行わない。
アカウント、フォロー、コメント、課金、広告、販売・在庫検索は対象外とする。
初期公開は無料・広告なしの個人運営を想定する。
