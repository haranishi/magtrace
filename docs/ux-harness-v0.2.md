# MAGTRACE UX改善ハーネス v0.2

- 実施日: 2026-08-29
- 対象: Figma v0.1 のホーム／分析結果（Desktop・Mobile）
- 目的: 「きれいな検索ダッシュボード」から、「気になる言葉の文脈を発見し、根拠まで辿れる文化探索体験」へ改善する

## 1. 参照した材料

### Obsidianメモ

- `UX_プロセスと評価.md`: UIとUXを分け、Discover → Define → Develop → Deliverを反復する
- `UI_コンポーネントとパターン.md`: Primary CTAは1画面1つ。Loading / Empty / Errorを必ず設計する
- `データ可視化の基礎.md`: 時系列は折れ線。タイトルで結論を言い、グレー＋1色、直接ラベル、注釈を使う
- `レイアウト・視覚的階層.md`: 1画面1主役、3段階以上の階層、8ptグリッド、内側余白より外側余白を大きくする
- `タイポグラフィ.md`: UI本文16px以上、Noto Sans JPとNoto Serif JPを2書体以内で使う
- `配色・カラー理論.md`: 60-30-10、本文4.5:1、色だけで意味を伝えない
- `アクセシビリティとUXライティング.md`: WCAG 2.2 AA、動詞型CTA、原因と回復手段を示すエラーコピー
- `デザイントレンド2026.md`: 普遍原則を基盤にし、トレンドは剥がせるアクセントとして限定する

### 外部リサーチ

- Google Trends: 時間推移、期間指定、関連トピック／関連クエリ、比較、記事への深掘り
- Google Arts & Culture: 検索だけでなくテーマ、人気トピック、年代から探索を始められる
- Datawrapper: 時系列は折れ線を基本とし、重要な変化へ直接注釈を置く
- NN/g: 探索検索ではサジェスト、フィルター、0件時の代替案、戻った際の状態保持が重要

## 2. 現行UIの課題

| ID | 課題 | 原則 | 影響 |
|---|---|---|---|
| UX-01 | ホームが機能説明中心で、触る前に価値を体験できない | 認識 > 記憶、段階的開示 | 初回検索率が伸びにくい |
| UX-02 | 分析画面のカードが同じ強さで、最初に読む結論が曖昧 | 1画面1主役 | 数字は見えるが発見になりにくい |
| UX-03 | 12か月の連続推移を縦棒で見せている | チャート選択 | 増減の流れを追いにくい |
| UX-04 | 関連語が静的リストで、次の探索に接続しない | 探索検索 | 回遊が途切れる |
| UX-05 | 期間、比較、出典、収録範囲の関係が分散している | 状態可視化、一貫性 | 数値の意味を誤解しやすい |
| UX-06 | モバイルに12px未満の補足が多く、検索の再実行も遠い | 可読性、操作効率 | 読み疲れと離脱につながる |
| UX-07 | Loading / Empty / Error / Cachedが未設計 | 状態可視化、回復支援 | 実装時に行き止まりが生まれる |
| UX-08 | 「関連語を掘る」「比較する」が独立したユーザーストーリーになっていない | 要件と画面の整合 | 実装優先度が曖昧になる |

## 3. 中心体験の再定義

> 気になる言葉を入力すると、「いつ増えた」「どの領域へ広がった」「何を読めば背景が分かる」が一続きで理解でき、次の問いへ進める。

### コアループ

`気になる言葉` → `一文の発見` → `推移と注釈` → `関連する文脈` → `代表記事・原典` → `次の言葉を掘る／比較する`

## 4. 追加ユーザーストーリー

### US-009: 関連する文脈を掘る

**As a** 企画の切り口を探すユーザー,
**I want to** 関連語を押して同じ分析を続けたい,
**So that** 最初の検索語から思いつかなかった文脈へ進める。

受け入れ条件:

- [ ] 関連語は押せるチップとして表示する
- [ ] `上昇中` と `よく一緒に出る` を区別し、色だけでなくラベルを付ける
- [ ] 遷移後も前の検索語へ戻れる探索履歴を保持する
- [ ] モバイルのタップ領域は44px以上にする

### US-010: 2つの言葉を比較する

**As a** テーマ候補を比較する企画担当者,
**I want to** 2つの検索語の推移を同じ期間で見たい,
**So that** どちらがいつ・どの媒体領域で伸びたか判断できる。

受け入れ条件:

- [ ] 分析画面から比較語を追加できる
- [ ] 線の色だけでなく、直接ラベルと線種で区別する
- [ ] 比較条件を共有URLに保存する
- [ ] 収録件数が少ない語には比較上の注意を表示する

## 5. v0.2画面構造

### ホーム

1. ヘッダー: ロゴ、使い方、データについて
2. ヒーロー: 可視ラベル付き検索、具体例、Primary CTA 1つ
3. `今日の見つけもの`: 実際の分析結果に近い一文＋小さな折れ線＋代表記事
4. `ことばの入口`: 社会、暮らし、カルチャー、仕事から選ぶトピックカード
5. データの約束: 収録範囲、CC BY、取得日、原典リンク

### 分析結果

1. 検索コンテキスト: 検索語、比較、期間、共有
2. `今回の発見`: 一文の結論、根拠となる3指標、収録範囲
3. 注釈付き折れ線: 直接ラベル、ピーク注釈、タップ／キーボードで値確認、表への切替
4. `文脈の広がり`: 押せる関連語チップと短い説明
5. `転機を読む3記事`: なぜ選ばれたかを表示し、NDL原典へ移動
6. 追従する次アクション: `別の言葉を調べる` / `比較する`

### 重要状態

- Loading: 検索語を維持したまま、要約・グラフ・記事のスケルトンを段階表示
- Empty: 表記変更例、短い語への修正、候補チップを表示
- Error: 原因を断定せず、再試行・検索語変更・キャッシュ結果の選択肢を表示
- Cached: 取得日時を表示し、更新を試す操作を提供

## 6. UIルール

- 背景 `#F6F1E8`、表面 `#FFFDF9`、本文 `#191817`、補助文字 `#69645C`、朱 `#B64027`
- 見出し Noto Serif JP、本文・UI Noto Sans JP
- Desktop 12カラム、Mobile 4カラム。余白は4/8ptスケールのみ
- Primary CTAは各画面1つ。朱色は全体の10%以下
- 折れ線以外はニュートラル。ピークは点・ラベル・注釈で示す
- 本文16px以上、補助情報12px以上、タップ領域44px以上
- フォーカスリング、キーボード操作、チャートのテーブル代替を仕様化する

## 7. 検証タスク

1. 「生成AIはいつ、どの領域へ広がったか説明してください」
2. 「生成AIから関連する次の検索語へ進んでください」
3. 「生成AIとAI教育を比較する入口を見つけてください」
4. 「グラフの根拠となる原典を1件開いてください」
5. 「0件になった後、別の検索で回復してください」

判定指標: タスク完了率、最初のクリック、完了時間、迷い発話、出典認知、収録範囲の理解。
